# 402 鼠王争霸赛 · 原生微信小程序

这不是 `web-view` 网页壳。`pages/` 是微信原生页面（WXML/WXSS/JS），`lib/api.js` 连接网页 V1 同一个 Supabase 项目，`lib/standings.js` 计算排行榜。使用正式 AppID `wxe5fcf6be56ed781e` 导入本目录即可在开发者工具中编译。没有使用或开通微信云开发。

## 当前已实现

- 首页从原项目的 `profiles`、`meals` 读取真实数据，展示主厨榜、菜品榜和最近一餐；沿用鼠王与厨师头像素材。
- 原生发布页：选照片、自动识别、改菜名、添加或删除漏识别菜品、重新识别、选择日期/午晚餐/厨师、上传到现有 Storage 并保存到现有 `meals`。
- 原生评委页：选餐次，按 0.5 分调整，由 Supabase Edge Function `mini-meal-update` 更新餐次和菜品分数。该函数要求已验证的 Supabase 用户 JWT，不使用 service role。
- 首页可主动选择微信头像并填写昵称；首次打开不会自动向微信申请登录凭证，也不读取微信号。用户主动保存资料时才建立小程序身份关联；头像和昵称只在用户选择后保存，资料和 OpenID 哈希映射仅由 `wechat-session` Edge Function 写入。
- 只在客户端使用可公开的 Supabase publishable key。SiliconFlow 密钥和微信 AppSecret 都只留在 Supabase Edge Function Secrets。
- 微信登录 Edge Function `wechat-session` 已部署，OpenID 会先做哈希再用于账号映射；真实微信登录码尚未在手机上走通验收。

## 当前发布状态与上线门槛

1. **后端与域名**：Supabase 项目状态为 `ACTIVE_HEALTHY`；`recognize-dishes`、`mini-meal-update`、`wechat-session` 三个 Edge Function 均处于 `ACTIVE`。用户确认已在微信后台保存 Supabase 的 request、downloadFile 域名；开发者工具中 `profiles`、`meals` 与 Auth 请求曾返回 HTTP 200。真机上的网络白名单、照片上传和图片回显仍待验证。
2. **真机端到端验收**：最新 1.0.2 已包含首页、发布、评委、管理餐次、管理厨师页面。仍需在手机上验证微信身份关联、照片识别与耗时、Storage 上传和回显、发布保存、评分保存，以及管理编辑/删除。自动化与模拟器检查没有新增或修改线上餐次、评分数据；真机验收也应先避免用生产数据做破坏性测试。
3. **微信身份**：`wx.login` → Supabase Edge Function → 微信 OpenID 的后端链路已部署，但真实微信登录码尚未在真机走通。微信号不能由小程序直接读取；头像和昵称仅在用户主动选择后保存。登录失败时会回退到匿名 Supabase 会话。
4. **微信隐私合规**：公众平台的《用户隐私保护指引》尚未核验；小程序调用 `wx.chooseMedia` 和 `chooseAvatar`，代码目前有用途说明，但没有接入小程序隐私授权回调。上线前必须在平台如实申报餐桌照片识别/保存、用户主动选择的头像和昵称，以及相关处理服务，并在真机验证同意、拒绝两条路径。
5. **备案**：小程序备案状态尚未确认完成。工信部要求境内从事互联网信息服务的 APP（包括小程序）履行备案手续，未备案不得提供该项互联网信息服务；应先在微信公众平台办理并确认备案，再进入正式审核发布流程。
6. **体验、审核、发布**：先在公众平台「管理 → 版本管理」将 1.0.2 开发版本设为体验版，生成体验版二维码并完成真机验收；验收通过且备案、隐私指引等平台配置齐备后，再由账号管理员提交审核。只有审核通过并执行发布，才算正式上线。本次明确没有提审或正式发布。
7. **访问权限按用户确认的共享模式执行**：用户已确认收到小程序链接的用户都应有权限。线上 RLS 允许任何匿名/已登录会话读取全部厨师和餐次，并更新或删除所有厨师与餐次；照片公开可读。分享链接不是身份验证，因此实际应按“拿到小程序即可操作共享数据”理解。Supabase 安全顾问报告匿名访问策略提示，符合当前共享模式但仍需接受其风险。
